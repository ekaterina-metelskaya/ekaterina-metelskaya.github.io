# Портфолио Екатерины Метельской

Статический сайт для GitHub Pages. Публикуется корень репозитория: `index.html` лежит здесь же, все пути относительные.

## Структура

```
index.html, projects.html   готовые страницы (собираются, руками не править)
cases/                      готовые страницы кейсов (собираются)
content/                    ТЕКСТЫ — правятся здесь
  home.md                   главная: о себе, подход, опыт, блок контактов
  projects.md               страница «Все проекты»
  production-control.md     кейсы: шапка (заголовок, лид, результат, факты, карточка) + текст
  planning.md
  documentation.md
  sweet-tv.md
  in-vino.md
  re-instance.md            только карточка, кейс в работе
  match-texts.json.gz       «Сработаемся?»: словарь готовых текстов результата (title, paragraphs, ai_paragraphs), сжат gzip.
                            Обновить: положить новый словарь как content/match-texts.json и запустить сборку —
                            архив пересоберётся сам; .json в git не попадает
templates/                  вёрстка
  index.html, projects.html шаблоны страниц
  cases/<кейс>.html         шаблон кейса: шапка, содержание, контакты
  cases/<кейс>.blocks.html  схемы и интерактивные демо, которые вставляются в текст
  partials/                 обложки-иллюстрации
css/  js/  assets/          стили, скрипты, шрифты, изображения, видео, CV
js/match-texts.js           собирается из content/match-texts.json.gz (руками не править)
tools/build.js              сборка: content + templates → готовые .html
tools/serve.js              локальный сервер для просмотра
tools/og.js, og*.html       картинки для превью ссылок: og-image-ru.png (сайт; og-image-en.png — для будущей /en/), assets/og (кейсы)
.nojekyll                   отключает Jekyll на GitHub Pages
```

## Как поменять текст

1. Откройте нужный файл в `content/` и поправьте текст.
2. Соберите сайт:
   ```bash
   node tools/build.js
   ```
3. Посмотрите результат: `node tools/serve.js` → http://localhost:5173
4. Закоммитьте и отправьте на GitHub вместе с пересобранными `.html`.

Нужен только Node.js, зависимостей нет.

## Аналитика

GA4 и Яндекс Метрика (счётчик **113747202**) запускаются только по согласию из баннера.
В Метрике включены Вебвизор, карта кликов, учёт внешних ссылок и точный показатель отказов;
остальные параметры сохранены из предоставленного кода счётчика, включая `ecommerce: 'dataLayer'`.
Оба загрузчика находятся в `templates/partials/gtag.html`. При отзыве согласия GA4
блокируется, Метрика останавливается через `destruct`, доступные сайту cookie счётчиков удаляются.
Инициализация Метрики ждёт загрузки скрипта и повторно проверяет согласие.
Повторное разрешение не загружает библиотеку второй раз.

Выбор хранится в `localStorage` под ключом `em-analytics-v2`. Старый ключ `em-analytics`
не используется: посетители должны увидеть новый баннер с упоминанием Метрики и Вебвизора.
Без JavaScript пиксель `noscript` не добавляется, так как баннер не может получить согласие.
Текстовые поля демо исключены из записи Вебвизора классом `ym-disable-keys`.
Пользовательские события из таблицы ниже отправляются в GA4 и в одноимённые
JavaScript-цели Метрики через `reachGoal`, с одинаковыми параметрами страницы и действия.
Дополнительно Метрика получает `scroll_depth_25/50/75/90`, `match_role_select`
и `match_task_select` (последние два — только для `action=select`). Эти цели позволяют
строить отдельные конверсии и составную цель «Сработаемся?» без объединения снятия и выбора.
Параметры `reachGoal` являются параметрами визита Метрики; их отчёты не следует
трактовать как точную копию событийной модели GA4. Общий контакт считается по
`contact_click`; дополнительный `match_contact` не суммируется с ним.
Во время загрузки библиотеки допускается очередь до 100 событий, полученных уже
после согласия. Она отправляется после `init` и очищается при отзыве или ошибке загрузки.
Отключение GA не блокирует отправку в Метрику, если общее согласие остаётся действующим.
Шлюз `emAnalytics.track` блокирует события до согласия и после его отзыва.
Старые клики не накапливаются. `js/analytics.js` подключается сборщиком на всех страницах
перед скриптами интерфейса. У всех событий есть `page_path` и `page_type` (home/case/other).

| Событие | Параметры и условие |
| --- | --- |
| `scroll_depth` | `percent_scrolled`: 25/50/75/90. На главной и в кейсах, один раз на порог за просмотр. Доля: нижняя граница экрана / высота страницы. При скачке учитываются все пройденные пороги. |
| `section_view` | `section_id`: ID раздела или hero. При первом попадании раздела в экран, один раз за просмотр. |
| `content_end` | Маркер после последнего раздела `.prose`, перед следующим кейсом и контактами; один раз за просмотр. |
| `ui_interaction` | `element`, `action`, `location`, `section_id`, `component` (номер фигуры в кейсе), иногда `value`. Клики в hero и шапке, элементы демо, вкладки/переключатели, раскрытие/сворачивание, изменения чекбоксов/ползунков. Стрелки в радиогруппах также учитываются. |
| `match_selection` | `group`: role/task/format/extra; `option`, `action`: select/deselect, `role` для задач, `location`: match. Включает снятие предыдущего выбора при смене роли/формата и при сбросе. |
| `match_result` | `role`, `task_count`, `format`, `extras`, `ai`, `result_key`, `result_state`, `location`: match. Сформированный результат при появлении его текста в экране; идентичный результат не отправляется повторно подряд. |
| `match_contact` | `channel`, `location`: match. Переход к контакту из результата, дополнительно к `contact_click`. |
| `cv_click` | `location`: header/contacts/contact/footer и `page_path` страницы. |
| `contact_click` | `channel`: telegram/email/linkedin, `location`: header/hero/match/contacts/contact/footer/page. |

Текст, введённый в демонстрационные формы, не попадает в параметры. Изображения
кейсов сейчас статические: событие открытия следует добавлять вместе с реальным
просмотрщиком, если он появится. Автоматическая анимация hero не считается кликами.
После согласия учитываются текущие видимые разделы и текущая глубина; ранее
пройденные и уже скрытые разделы не восстанавливаются. Возврат через bfcache сохраняет
счётчики текущего просмотра, обычная загрузка страницы начинает новый просмотр.

Проверка: `node tools/build.js` и `node --test tools/analytics.test.js`.
Тесты проверяют согласие, пороги, дедупликацию, видимость результата, контакты/CV
и подключение скрипта/маркера во всех собранных страницах.

### Разметка текста

- Пустая строка — новый абзац. `**жирный**`, `*курсив*`, `[ссылка](https://…)`.
- Списки: строки с `- ` или `1. `.
- `## Заголовок {#id}` — раздел кейса. В фигурных скобках настройки раздела, их лучше не трогать:
  `label="Решение 01"` — подпись над заголовком, `toc="…"` — короткое название в содержании,
  `sub="01"` — пункт вложен в содержании, `.finale` — оформление итогового раздела.
- Врезка «Что вынесла»:
  ```
  > **Что вынесла**
  >
  > Текст врезки.
  ```
- `[[solution-1-fig]]` — место, куда встаёт схема из `templates/cases/<кейс>.blocks.html`. Строку можно переносить между абзацами, но не удалять случайно.
- Шапка файла между `---` — поля «ключ: значение». Списки (теги, факты) — строками `  - …`. В фактах формат `Подпись: значение`.

Если в тексте ссылка на несуществующий блок или в шаблоне нет значения для поля, сборка остановится с ошибкой и подскажет файл.

## Публикация на GitHub Pages

1. Создайте репозиторий и загрузите в него содержимое этой папки (не саму папку): в корне репозитория должны оказаться `index.html` и `.nojekyll`.
2. Settings → Pages → Build and deployment → Source: **Deploy from a branch**, ветка `main`, папка `/ (root)`.
3. Через минуту сайт откроется по адресу `https://<логин>.github.io/<репозиторий>/`.
4. Превью ссылок ссылаются на https://metelskaya.design. Для другого адреса соберите сайт так:
   ```bash
   SITE_URL=https://<адрес> node tools/build.js
   ```
